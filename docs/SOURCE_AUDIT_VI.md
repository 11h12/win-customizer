# Đối chiếu quy trình ManHPC: rebuild ISO và answer file

Tài liệu này tách các thao tác có thể làm trong toolkit khỏi thao tác chỉ áp dụng cho VMware/UI bên ngoài. Các đường dẫn `D:\LAB\...` bên dưới là đường dẫn ví dụ trong bài ManHPC, không phải mặc định đúng trên mọi máy.

## 1. Sau khi capture: thứ tự các bước trong bài rebuild

### Bản cài một image

1. **Capture từ WinPE rồi tắt máy.** Bài dùng `Dism /Capture-Image /ImageFile:C:\install.wim /CaptureDir:E:\ /Name:"Windows 10 Enterprise No Software" /compress:max`; trước đó phải dùng `diskpart`/`list vol` để xác định ký tự volume trong WinPE. Bài yêu cầu thoát Command Prompt và tắt máy sau khi capture. Ký tự ổ WinPE không nên mặc định hóa: `/CaptureDir` là volume Windows cần thu, `/ImageFile` là nơi lưu WIM. DISM xác nhận cú pháp này và hỗ trợ các cờ tùy chọn `/CheckIntegrity`, `/Verify`. ([ManHPC, capture](https://manhpc.com/huong-dan-rebuild-bo-cai-windows-phan-3/); [Microsoft, DISM Capture-Image](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/dism-image-management-command-line-options-s14?view=windows-10))
2. **Đưa WIM khỏi WinPE sang thư mục làm việc của máy kỹ thuật.** Trong ví dụ VMware, bài map ổ `BACKUP.vmdk`, rồi copy `install.wim` sang `D:\LAB\source\21H1\x86`. Đây là đường dẫn đích cụ thể cần giữ nguyên làm ví dụ trong hướng dẫn/script; cho phép người dùng chọn đường dẫn thật. Việc map VMDK là thao tác VMware, không phải bước Windows/DISM tự làm. ([ManHPC, phần hoàn thiện ISO](https://manhpc.com/huong-dan-rebuild-bo-cai-windows-phan-3/))
3. **Sửa metadata image.** Mở WIM trong GImageX hoặc NTLite, vào phần Change, đặt Description và SKU flag theo edition, lưu, rồi xem lại tab Info. Bài không đưa bảng SKU flag hay lệnh DISM để sửa flag; không được suy diễn flag từ tên image. Nếu dùng công cụ khác, phải kiểm tra lại thông tin/index trước khi tiếp tục. ([ManHPC](https://manhpc.com/huong-dan-rebuild-bo-cai-windows-phan-3/))
4. **Thay image trong ISO gốc và lưu thành ISO mới.** Mở ISO gốc bằng UltraISO, thay `sources\install.wim` bằng WIM vừa xử lý (bài cho phép `install.esd`), sau đó `Save As` thành file ISO mới. Không ghi đè ISO gốc. Đây là thao tác GUI bên thứ ba trong bài; Microsoft xác nhận quản lý/capture WIM bằng DISM nhưng không đặc tả thao tác chỉnh sửa ISO bằng UltraISO. ([ManHPC](https://manhpc.com/huong-dan-rebuild-bo-cai-windows-phan-3/); [Microsoft, DISM image management](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/dism-image-management-command-line-options-s14?view=windows-10))

### Khi tạo nhiều image trong cùng `install.wim`

1. Tạo/capture image thứ hai theo quy trình build/capture tương ứng, rồi sửa Description/SKU flag và kiểm tra Info như ở trên.
2. Bài xuất image từ `D:\LAB\source\21H1\x86-2` vào bộ `install.wim` tại `D:\LAB\source\21H1\x86`; khi NTLite hỏi ghi đè, chọn **No**. Ý đồ là giữ image trước và thêm image mới, nhưng bài không mô tả chính xác hộp thoại hay thao tác NTLite bên dưới; sau bước này bắt buộc đọc lại danh sách index bằng `DISM /Get-ImageInfo` để xác nhận cả image cũ và mới còn trong WIM. Phương án DISM chính thức để nối thêm một volume image là `/Append-Image`; mỗi lần thêm nhận index mới. ([ManHPC](https://manhpc.com/huong-dan-rebuild-bo-cai-windows-phan-3/); [Microsoft, append images](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/append-a-volume-image-to-an-existing-image-using-dism--s14?view=windows-11))
3. **Nhập default app associations vào đúng index.** Bài mount image thứ 2 của `install.wim` tại `D:\LAB\mount`, đưa `AppAssociations.xml` vào image bằng DISM, kiểm tra bằng `/Get-DefaultAppAssociations`, rồi unmount và commit. File XML trong ví dụ nằm tại `D:\LAB\source\21H1\AppAssociations\x86\AppAssociations.xml`. Đường dẫn trong lệnh được in ở bài là `D:LAB\mount` (thiếu `\` sau dấu hai chấm); phải dùng đường dẫn hợp lệ như `D:\LAB\mount`. Microsoft xác nhận trình tự mount → import → get/verify → unmount/commit. ([ManHPC](https://manhpc.com/huong-dan-rebuild-bo-cai-windows-phan-3/); [Microsoft, export/import associations](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/export-or-import-default-application-associations?view=windows-11))
4. **Đóng gói và kiểm tra ISO.** Bài nói có thể đổi WIM sang ESD để giảm dung lượng, nhưng không nêu lệnh chuyển đổi hay chỉ ra chính xác các index cần xuất. Microsoft ghi rõ cách xuất từng index: `DISM /Export-Image /SourceImageFile:<install.wim> /SourceIndex:<n> /DestinationImageFile:<install.esd> /Compress:recovery`; cần lặp riêng từng index nếu muốn giữ nhiều edition/image rồi xác nhận bằng `/Get-ImageInfo`. ([ManHPC](https://manhpc.com/huong-dan-rebuild-bo-cai-windows-phan-3/); [Microsoft, DISM Export-Image](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/dism-image-management-command-line-options-s14?view=windows-10))

### Nếu làm bộ cài đa kiến trúc

Bài dùng ISO Microsoft có cấu trúc `boot`, `efi`, `x64`, `x86`; thay nội dung các folder `x64`/`x86` bằng nội dung media tương ứng, rồi thay riêng `x64\sources\install.wim` hoặc `x86\sources\install.wim` bằng image đã build. Với ISO Windows 11 đơn giản, bài nói thay image trong folder `sources` ở gốc. Sau chỉnh sửa lưu thành ISO mới. Nếu có `autounattend.xml`, bài đặt file cạnh `setup.exe` trong thư mục gốc media. Chỉnh boot menu bằng BOOTICE (BCD Legacy và EFI) là phần tùy chọn riêng, không phải bước cần có để thay image. ([ManHPC, đa kiến trúc](https://manhpc.com/huong-dan-rebuild-bo-cai-windows-phan-3/))

### Các bước chỉ dành cho môi trường VMware/UI và nên để ngoài toolkit

- Tạo/cấu hình máy ảo, gắn ISO, chỉnh boot order, snapshot/revert snapshot.
- Cấu hình Start trong user của máy dựng, export `LayoutModification.xml`, chép/sửa `DefaultLayouts.xml` rồi trả lại image trước capture. Menu 1 của toolkit chỉ export Start layout làm bản lưu; file được copy ở menu post-capture không tự được import vào WIM.
- Thêm VMDK `BACKUP`, khởi tạo/format ổ và gán nhãn `BACKUP` trong Disk Management.
- Tắt máy ảo, unmount/map `BACKUP.vmdk` từ VMware trên máy host, rồi duyệt/copy tệp thủ công.
- Các thao tác GUI riêng của GImageX, NTLite, UltraISO/BOOTICE. Toolkit có thể chạy các phần DISM và theo dõi từng lệnh; nó không thể tự map VMDK hoặc thao tác hộp thoại của những ứng dụng này nếu không có công cụ/CLI được xác nhận.
- Cài thử ISO sau khi build và kiểm tra desktop/Start/apps trong VM; toolkit chỉ verify cấu trúc ISO và danh sách install image bằng DISM, không điều khiển cài Windows.

## 2. Hai answer file làm việc ở giai đoạn nào

| Tệp | Vị trí/điểm phát hiện | Pass và nhiệm vụ |
|---|---|---|
| `autounattend.xml` | Gốc USB/DVD/ISO, cạnh `setup.exe`; Windows Setup tự tìm tên này khi khởi động từ media | Chủ yếu `windowsPE`: ngôn ngữ giao diện Setup, chọn image/đĩa/phân vùng, key và các thiết lập của Windows Setup. Bài ManHPC ghi file mẫu chỉ có `windowsPE`; file có thể chứa thêm pass khác nhưng vị trí/tên vẫn để Setup phát hiện. |
| `unattend.xml` | Trong ảnh tham chiếu, `C:\Windows\System32\Sysprep`; chọn rõ với `/unattend:<đường-dẫn>` khi chạy Sysprep | Các pass cho quá trình reseal/deploy: `generalize` chuẩn bị ảnh dùng lại; `specialize` áp thiết lập cho máy đích và là nơi ví dụ dùng `CopyProfile`/múi giờ; `oobeSystem` chạy trước Windows Welcome/OOBE để cấu hình ngôn ngữ vùng, tài khoản, và các trang OOBE; một số `FirstLogonCommands` chạy khi user đăng nhập lần đầu. Bài đặt file này trong Sysprep folder. |

Bài Part 5 có ví dụ en-US (`InputLocale 1033:00000409`, `SystemLocale`, `UILanguage`, `UserLocale`) và `SE Asia Standard Time`; đó là giá trị mẫu, không phải bộ giá trị dùng chung. Toolkit hỏi lựa chọn thực tế cho ngôn ngữ hiển thị, ngôn ngữ hệ thống, định dạng vùng/quốc gia, bàn phím và múi giờ; bốn locale/ngôn ngữ/bàn phím bắt buộc, còn múi giờ có thể bỏ. `UserLocale` và `TimeZone` là hai thiết lập khác nhau. Microsoft xác định `UserLocale` là mã locale dạng language-region, dùng cho định dạng ngày/giờ/tiền tệ/số, và cho biết vùng người dùng có thể được đặt qua `UserLocale`; `InputLocale` riêng điều khiển ngôn ngữ nhập và layout bàn phím. ([ManHPC Part 5](https://manhpc.com/huong-dan-tao-va-cau-hinh-file-tra-loi-tu-dong-unattend-xml-phan-5/); [Microsoft, UserLocale](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-international-core-userlocale); [Microsoft, InputLocale](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-international-core-inputlocale); [Microsoft, pass overview](https://learn.microsoft.com/en-gb/windows-hardware/manufacture/desktop/how-configuration-passes-work?view=windows-11); [Microsoft, automate OOBE](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/automate-oobe?view=windows-11))

ManHPC Part 2 đặt ProductKey trong `autounattend.xml` → `windowsPE` → `Microsoft-Windows-Setup\UserData`. Đó là khóa để Windows Setup chọn edition; Microsoft phân biệt nó với `Microsoft-Windows-Shell-Setup\ProductKey` trong pass `specialize` dùng cho activation. Toolkit thêm post-capture task 16 để tạo file windowsPE độc lập, với preset Pro, key tự nhập hoặc bỏ key; task Build ISO có checkpoint đặt file ở gốc media cạnh `setup.exe`. Preset Pro không phải license kích hoạt. Với WIM có nhiều index cùng edition, product key không xác định index duy nhất; cần `ImageInstall\OSImage\InstallFrom\MetaData`. ([ManHPC Part 2](https://manhpc.com/huong-dan-tao-va-cau-hinh-file-tra-loi-tu-dong-unattend-xml-phan-2/); [Microsoft, ProductKey under UserData](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-setup-userdata-productkey); [Microsoft, product keys and activation](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/work-with-product-keys-and-activation-auth-phases?view=windows-11); [Microsoft, image selection metadata](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-setup-imageinstall-osimage-installfrom-metadata-key))

`Microsoft-Windows-Shell-Setup\OOBE\ProtectYourPC` được hỗ trợ trong pass `oobeSystem`. Microsoft định nghĩa `1`/`2` là bật Express settings và `3` là tắt Express settings. Toolkit task 16 có thể thêm đúng component/pass này vào `autounattend.xml`; bỏ qua prompt thì setting không được ghi, để OOBE xử lý theo mặc định. Đây là setting Express settings, không phải các giá trị riêng cho từng privacy toggle mới trên màn hình Privacy của Windows 11. Tài liệu Microsoft mô tả màn hình Privacy riêng trong OOBE nhưng danh sách setting tự động hóa OOBE chỉ nêu `ProtectYourPC` cho Express settings; vì vậy toolkit không tuyên bố tự chọn hoặc ẩn từng privacy toggle. ([Microsoft, ProtectYourPC](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-shell-setup-oobe-protectyourpc); [Microsoft, Automate OOBE](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/automate-oobe?view=windows-11); [Microsoft, Windows 11 OOBE flow](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/customize-oobe-in-windows-11))

Microsoft nêu rõ OOBE page nào không được cấu hình trong answer file thì vẫn hiện; muốn tự động hóa phải cung cấp các giá trị cần thiết và chỉ ẩn những trang có setting tương ứng. Microsoft khuyến cáo **không** dùng `SkipMachineOOBE` để tự động hóa OOBE; cấu hình locale, account/password và `Shell-Setup\OOBE` thay vì bê nguyên mẫu có các cờ `Skip*` trong bài. `HideLocalAccountScreen` chỉ áp dụng Windows Server, không phải cách ẩn trang tài khoản local trên Windows Client. ([Microsoft, automate OOBE](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/automate-oobe?view=windows-11); [Microsoft, HideLocalAccountScreen](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-shell-setup-oobe-hidelocalaccountscreen))

`HideEULAPage` đúng hierarchy là `oobeSystem → Microsoft-Windows-Shell-Setup → OOBE`, nhưng Microsoft giới hạn việc dùng setting này cho OEM/System Builder testing trước khi xuất xưởng. Toolkit không bật setting này theo mặc định và chỉ ghi nó khi người dùng chọn Yes. ([Microsoft, OOBE settings](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-shell-setup-oobe))

`CopyProfile` chỉ được ghi dưới `specialize → Microsoft-Windows-Shell-Setup`; bật nó khi profile built-in Administrator trong Audit Mode đã được cấu hình. `PersistAllDeviceInstalls` chỉ được ghi dưới `generalize → Microsoft-Windows-PnpSysprep` và chỉ dành cho phần cứng giống hệt. Múi giờ thuộc `Microsoft-Windows-Shell-Setup\TimeZone`; locale/keyboard thuộc `oobeSystem → Microsoft-Windows-International-Core`; tài khoản local và các OOBE flags thuộc `oobeSystem → Microsoft-Windows-Shell-Setup`. Trước khi Sysprep, validator của toolkit kiểm tra các component/pass, architecture thống nhất, bốn locale bắt buộc, setting trùng, cấu trúc tài khoản/password, timezone và UI language đã cài; Windows SIM với catalog đúng image vẫn là xác thực cuối cùng. ([Microsoft, CopyProfile](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-shell-setup-copyprofile); [Microsoft, PersistAllDeviceInstalls](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-pnpsysprep-persistalldeviceinstalls); [Microsoft, TimeZone](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-shell-setup-timezone); [Microsoft, International-Core](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-international-core); [Microsoft, LocalAccount Password](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-shell-setup-useraccounts-localaccounts-localaccount-password))

Khi `UserAccounts` tạo tài khoản qua answer file, Windows có thể bỏ qua trang tạo user trong OOBE. Microsoft khuyên bảo đảm có một tài khoản Administrators để còn quản trị thiết bị; vì toolkit chỉ tạo một tài khoản nên trường `Group` của nó được khóa thành `Administrators`. Nếu cần tài khoản thường, tạo thêm sau khi đăng nhập tài khoản quản trị. ([Microsoft, UserAccounts/OOBE behavior](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-shell-setup-autologon); [Microsoft, LocalAccount Group](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-shell-setup-useraccounts-localaccounts-localaccount-group))

Kiến trúc component trong `unattend.xml` được lấy từ Windows đang chạy và bị kiểm tra lại trước Sysprep. Khi bật `CopyProfile`, toolkit xác nhận profile SID-RID 500 tồn tại và chặn nếu còn profile người dùng khác; điều này tránh để Sysprep chọn nhầm profile.

Vì Windows Setup có thể cache answer file đã dùng trước đó, khi chạy Sysprep cần chỉ định đúng file đã tạo bằng `/unattend:...`; Microsoft lưu ý answer file cache được dùng ở những pass sau nếu không chỉ định file khác. Không đặt file generated của máy vào `autounattend.xml` mặc định trong ISO nếu mục tiêu là cấu hình pass `generalize`/`specialize`/`oobeSystem` cho lần deploy. ([Microsoft, answer files with Sysprep](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/use-answer-files-with-sysprep?view=windows-11); [Microsoft, answer-file search/caching](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/windows-setup-automation-overview?view=windows-11))

## 3. Điểm cần kiểm tra trước khi biến tài liệu thành tự động hóa

- Các thư mục `21H1`, `x86`, `x86-2`, `AppAssociations\x86` là ví dụ riêng của tác giả; yêu cầu script lấy đường dẫn thực tế và giữ cấu trúc ISO đã chọn.
- Lệnh import association có lỗi thiếu dấu `\` trong bài; không chép nguyên văn.
- Bài không nói đủ cách hiểu lựa chọn “No” của NTLite, cách tạo ESD, cách giữ metadata khi export từng index, hay cách xử lý mọi biến thể `install.wim`/`install.esd`. Dùng `Get-ImageInfo`/`Get-WimInfo` để xác nhận index và metadata ở mỗi ranh giới; không tuyên bố thành công chỉ dựa vào hộp thoại.
- Bài Part 5 gộp cả mẫu Windows 7/10/11 và component cho x86/amd64; chọn đúng architecture, phiên bản/edition và pass cho image đang dùng, rồi validate bằng Windows SIM. Microsoft yêu cầu validate answer file trên image/catalog tương ứng; Windows SIM cũng cảnh báo lỗi nếu architecture của answer file và image lệch nhau. Không sao chép nguyên file mẫu vào image khác mà chưa kiểm tra component/settings. ([Microsoft, best practices](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/wsim/best-practices-for-authoring-answer-files); [Microsoft, validate](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/wsim/validate-an-answer-file); [Microsoft, open answer file](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/wsim/create-or-open-an-answer-file))
- Quy trình kỹ thuật của người dùng vẫn phải hoàn tất OOBE bằng tài khoản tạm trước, sau đó mới vào Audit để cấu hình/capture; tài liệu về answer file ở đây giải thích cách Windows áp dụng pass sau khi image được reseal, không phải chỉ dẫn thay đổi quy trình đó.
